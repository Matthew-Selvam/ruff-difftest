## The 2 fixed-side converge failures are the known E302 repro

Both are `debug error: Failed to converge after 100 iterations ... rule codes
E302`:

- `pycodestyle/E30.py` — the indented-comment repro already documented in
  `2026-10-05-e302-indented-comment-nonconvergence.md`. The patched build's
  final output leaves the comment directly followed by the next `def` with
  only one blank line (E302 unsatisfied), oscillating internally between E302
  insertion and E303 removal. File content is stable across CLI invocations;
  only the internal 100-round loop trips.
- `pyupgrade/UP028_0.py` — same shape inside a `yield`-bearing generator
  fixture: indented `# Comment four` trailing a body, then a dedented line.

Both converge to stable content by the second CLI invocation; the failure is
inside ruff's single-invocation fix loop, not run-to-run nondeterminism.

## The 5 base-side converge failures are the patch working as intended

All five fail under **base** with `Failed to converge` and pass cleanly under
the patched build (run 1 and run 2 both clean, zero remaining E30x/I001
errors afterwards):

- `pycodestyle/E30_comment_before_definition.py` (E302)
- `isort/insert_empty_lines.py` (E302)
- `Lib/test/_test_embed_structseq.py` (E302)
- `Lib/test/test_inspect/inspect_fodder.py` (I001)
- `flake8_return/RET503.py` (I001)

Net convergence delta: base 5 → fixed 2, i.e. the patch fixes three more
non-convergence cases than it introduces.

## The 13 differing files

All differ only in blank-line placement around comment blocks (base puts two
blanks before a `###`/`#---` banner or after it; patched normalizes to the
comment-block anchoring), and all 13 have `base_format_disagrees` AND
`fixed_format_disagrees` true — the check→format disagreement pre-exists in
the unpatched build, so none flags as a patched-only regression:

Lib/logging/__init__.py, Lib/string.py, Lib/tarfile.py,
Lib/test/_test_embed_structseq.py, Lib/test/test_gc.py,
Lib/test/test_inspect/inspect_fodder.py, Lib/test/test_smtplib.py,
flake8_return/RET503.py, isort/insert_empty_lines.py, pycodestyle/E30.py,
pycodestyle/E30_comment_before_definition.py, pyupgrade/UP028_0.py,
ruff/RUF023.py.

Representative diff (Lib/string.py): base collapses a single blank between
`printable = ...` and the following comment block; patched keeps two. These
are formatting-convention shifts consistent with the patch's comment-block
anchoring, each already present in base's check→format disagreement.

## Bisect attempt on the E302 non-convergence

Minimal-window bisection of `pycodestyle/E30.py` found no window ≤100 lines
(and no file prefix) that triggers the fixed-build non-convergence: the
oscillation needs whole-file context. The standalone repro from the earlier
finding still reproduces exactly (fixed leaves `# comment` directly before
`def test_clientmodel` with no blank line; base inserts two). A candidate
refinement remains anchoring only when the comment's indentation is
compatible with the following logical line — a patch-author design call.
